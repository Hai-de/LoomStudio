# Timeline 工作空间与 VFS 组织计划

> **状态**：讨论记录 / 部分方向已确认，未授权业务实施
> **更新**：2026-10-16
> **范围**：保存本轮工作空间、资源归属、目录与存储讨论；不代替文件级实施设计，不启动迁移。

## 1. 需求与已确认边界

需要一个属于当前 Timeline 的开放、持久工作空间，主要承载：

- Session 交接使用的摘要与工作材料。
- 多 Agent 共同维护的暗线、计划、草稿和其他游玩产出。
- 生成图片等二进制，以及可保存、复用的脚本。

这些内容是游玩数据，跨 Timeline 默认不共享；迁移或复制应是明确动作。“临时”指运行用途，不表示退出或重启即可清理。剧情退回历史节点时，工作空间必须恢复到对应历史状态。这条要求已明确，但重试、Swipe、分支、删除怎样共用恢复合同，仍需主任务收束；本计划不自行落实新的协调层。

文档类文本以 Markdown 为方向；另允许脚本和二进制，不把“文本用 MD”解释成禁止 JS。保存脚本不授予额外执行权限，具体 CodeAct 文件执行入口尚未确定。

Lore 与工作空间不是同一种内容：Lore 承担条件上下文，工作空间承担材料保存与协作。工作文件不因存在就自动注入 Prompt，也不自动成为 Lore Entry。需要 Lore 触发能力时走 Lore 的消费合同；游玩专属内容不能因此写入共享作者资源。Timeline 专属 Lore 的完整存储与恢复能力尚需核对。

## 2. 本轮源码核对事实

### 资源树与路径

现有 Prompt Resource 内部已有稳定节点身份与父子树，使用 resourceId、parentId、label、orderIndex 等组织，不以完整路径字符串作为节点身份。因而不应把“更原生的 VFS”理解为从零重建文件树。

- [实时资源 VFS](../../../packages/application-runtime/src/vfs/resource-filesystem.ts)：将本次允许访问的资源平铺于 `/resources/<资源名称>/`；预设与 Lore 共用这一层，路径不区分角色与全局来源。按名称生成路径、转义特殊字符，同级重名追加 ID 哈希。
- 节点有正文且无子节点时显示为文件；脚本叶节点补 `.js`，其他正文叶节点补 `.md`。节点有子节点或无正文时显示为目录；目录自身正文投影为 `@body.md`。作者模式另显示元数据 YAML；默认游玩模式隐藏停用节点与元数据。
- 路径内部绑定资源 ID、节点 ID、版本及字段，写入回到领域接口，不写宿主磁盘路径；当前作用域有路径身份重绑保护。
- [上下文 VFS](../../../packages/application-runtime/src/vfs/vfs-gateway.ts)：另从 SourceNode / PromptContribution 生成 `/context`，标记 injected、not-triggered、agent-only；它是准备时的投影，不是可写源文件。其命名规则与实时资源视图不完全相同。
- [资源选择](../../../packages/application-runtime/src/agents/agent-turn.ts)与 [CodeAct 接线](../../../packages/application-runtime/src/agents/codeact/context.ts)：资源先按本轮使用关系和可用性进入作用域，再组装文件视图。

### 存储与恢复基础

已有共享 SQLite Data Engine、迁移、事务与提交事实，以及不可变 Blob 字节存储；它们可复用，但不自动提供新领域的树版本或 Timeline 历史恢复。

当前正文与 State 已有共同恢复调用，工作空间尚未接入；共享 Lore 编辑历史不等于剧情分支隔离。Session 原始 Transcript 属于执行事实，不应变成任意可覆写的工作文件。现有工作交接入口接受已经生成的摘要，不代表自动摘要与 Scratchpad 工作流已完成。

上述边界参见[数据能力与生命周期](../../architecture/application/data-capabilities-and-lifecycle.md)、[剧情上下文及交接](../../architecture/application/extension/narrative-context.md)。本轮仅做源码阅读，没有运行行为测试。

## 3. 目录组织方向

用户认可工作空间与作者资源分开；使用 `/workspace` 比 `/TMP` 更能表达持久游玩数据。以下是讨论示意，不是已冻结的公共路径 Schema：

```text
/
├── resources/                 # 本轮可用作者内容
│   ├── character/             # 角色所属的 Lore 等
│   ├── global/                # 公共 Lore 等
│   └── preset/                # 预设本身
├── assets/                    # 随角色、扩展等来源提供的素材
│   ├── character/…
│   ├── extensions/…
│   └── backgrounds/…
├── workspace/                 # 当前 Timeline / 分支的工作内容
│   ├── 交接.md
│   ├── 暗线/…
│   ├── 草稿/…
│   ├── scripts/…
│   └── assets/…
├── narrative/
├── state/
└── context/
```

工作空间内部目录是使用示例，不要求预建。顶层 Assets 按来源与内部分类组织；背景目录如何对应真实来源待核对，不把背景选择配置当作图片文件。

用户提出：随包自带的图片和二进制可挂载真实包文件，无需为统一 VFS 强制复制到 Blob；工作空间生成内容可进入 Blob。引用应使用受控虚拟路径或稳定资产引用，而非不可移植的宿主绝对路径。现有 Blob 同样服务部分导入资产，不能把讨论中的分工当作当前事实，也未授权迁移既有资产。

Lore 以 MD 内容为主，图片可引用 Assets，无需强制与 Alice.md 同目录放 Alice.png。Assets 的存在不等于自动读入模型。

作者携带初始工作文件的需求已提出；建议在创建 Timeline 时实例化为独立工作树，后续模板更新不覆盖游玩内容。模板放置路径、初始化时机和复制语义仍待确认。

## 4. 归属、引用与可见路径

角色与全局来源分组能够辅助 AI 查找内容、理解范围和判断修改影响。它是语义线索，不自动规定角色内容优先于全局内容，也不是权限依据的替代品。

建议保留现有几种关系，避免强行把使用关系压成所有权树：

- **稳定身份与归属**：资源只有明确的所有者和生命周期。
- **引用与绑定**：决定哪些角色、预设或 Timeline 使用它，不改变所有权。
- **Agent 挂载视图**：组织本次可访问资源，路径解析到稳定身份。

例如公共衣物 Lore 被 Alice 与 Bob 同时引用，两次执行均可在 `/resources/global/lore/衣物/` 看见同一资源，而非各自产生私有副本。被预设引用的 Lore 也不因此归属预设。跨角色私有资源是否允许引用，继续服从实际权限合同，不由示例授权。

若未来同一资源有多个路径入口，它们只能是明确的别名或挂载；当前没有决定引入重复入口。引用不移动资源，复制才创建独立身份。此节为本轮建议，公共目录协议和归属映射仍待定稿。

## 5. 目录正文与文件模型建议

用户质疑目录同时带正文的必要性，倾向用普通 README 等文件承载内容。建议目标模型为目录负责组织、文件负责正文，减少 `@body.md` 特例；README 可选，不是隐藏目录正文的另一种名字。

目录仍可拥有启用、触发及继承配置，不能因取消目录正文就删除这些业务语义。已有正文可按用途变为 README.md、概述.md、共同设定.md 等普通文件，名称不自动决定注入。

此调整尚未授权实施。迁移前必须核对注入顺序、角色、触发继承、稳定节点引用与历史版本；只把 body 搬成子文件不能证明行为等价。

## 6. 是否新增统一路径 KV

当前建议：不为 VFS 先创建一份全局“完整路径 → 数据”的权威 KV。现有归属、安装记录和父子树可以解析的关系，不重复持久化。

| 层 | 当前建议 |
| --- | --- |
| 固定根入口 | 宿主组合，不必持久化 |
| 包文件挂载 | 优先根据安装、归属和 Manifest 解析，不为每个包文件建数据库副本 |
| 可变工作目录 | 持久化身份、父目录、名称、类型、内容引用和版本归属 |
| 自定义挂载或别名 | 确有需求后，再保存不能从现有事实推导的关系 |

父目录 ID 加名称可以直接表达原生目录，路径不是必须保存的主键。统一 VFS 也不要求资源表、包文件和 Blob 使用同一张表。

真正需要补齐的是统一路径解析、领域操作边界，以及工作空间树版本。树版本必须覆盖创建、删除、重命名、移动和内容变化，只有文件正文历史不够。本节尚未确定专用表、Document Store 或具体版本结构。

## 7. 后续收束与验收问题

1. 定稿目录轴：来源分组、资源种类、包身份如何组合；路径命名、重名、稳定引用与搬移规则。
2. 核对现有资源树、包文件、Assets 和导出导入能复用的具体合同，避免形成第二份目录权威数据。
3. 与主任务协调 Timeline 恢复合同：历史节点、执行前基线、候选完成后的工作树版本如何捕获；重试、Swipe、分支与剧情回退共用恢复入口。
4. 明确并发和迟到写入：历史切换后旧任务不能写入新分支视图；多 Agent 文件修改不能静默覆盖。
5. 明确初始化、Session 摘要采用、权限、存档携带、删除与 Blob 历史引用保留。
6. 上述合同确认后再制定文件级实施方案；不先做通用 VFS 数据库或万能回滚框架。

后续行为验收至少需要覆盖：共享资源双角色引用仍是同一身份；来源目录不扩大权限；生成素材和文件移动随工作树恢复；包素材不随剧情回退被改写；失败不发布部分目录状态；旧任务迟到提交被拒绝；存档恢复保留引用。这里只记录验收方向，没有新增或执行测试。
