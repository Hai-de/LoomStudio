# Agent 执行上限调整

状态：已实现，待真实 Session 使用验收。

## 当前事实与已确认决定

Agent Tool Loop 硬编码最多 8 轮 Provider 调用、单工具 30 秒超时；CodeAct 每次最多 128 个 ctx 请求、8 个并发请求，超限统一报 `codeact.call_limit`。

取消 Provider 轮数上限与统一工具超时，继续传播用户暂停/取消信号。CodeAct 取消 ctx 累计次数上限，并将超出并发容量的调用排队，宿主仍校验桥接协议与并发容量。目录、正文、内存及输出大小的既有边界不变。

CodeAct 的 JavaScript 执行期限继续用于中断无限循环或永不完成的 Guest Promise；宿主 ctx 操作（包括网络与审批）等待不计入该期限。不存在 API 等待 10 秒或 30 秒后被外层统一打断的行为。

## 边界与验证

只修改 Tool Loop 及 CodeAct 协议、宿主、Worker。不修改提供商自身请求策略、权限审批、数据库或恢复点格式。恢复沿用 Provider step 编号，但不再受第 8 轮门槛阻断。

定向验证：超过 8 轮可完成；普通工具超过原时限不被外层中断；CodeAct 顺序超过 128 次和并行超过 8 次可完成；宿主等待不耗用 JS 预算；手动取消与死循环隔离依旧生效。使用现有测试，不请求真实模型或生图服务。

## 验证结果

54 项定向测试通过，覆盖超过 8 轮、普通工具等待超过 30 秒、CodeAct 顺序 160 次与并行 24 次调用、宿主长等待、死循环中断及暂停恢复。Runtime 类型检查通过，开发构建已同步。扩大检查另有 3 项既有返回结构/冲突错误码断言不匹配，未修改相关协议或断言；未调用真实模型、生图服务。
