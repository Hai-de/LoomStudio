## 首阶段实施前事实

- Studio 只有一个活动工作面板；Model、设置、扩展管理当前均替换该面板。
- 通用 Dialog 使用原生 dialog / Top Layer，已有关闭、Esc、遮罩及标题语义。
- Model 复用现有 Provider 账号表单、连接编辑和模型列表；本次不改变 API、凭据与模型消费合同。
- 工作区已有其他任务的修改，本计划只增量修改相关职责。

## 已确认方向与实施范围

工作区承载主要任务；设置、模型服务和扩展管理逐步采用保留原工作现场的居中工具浮层。第一阶段实施 Model 并建立可复用的 Dialog workbench 布局；用户确认方向后，第二阶段迁移设置与扩展管理。扩展贡献的实际工作界面保留在工作区。

用户已授权计划后开始 Model 端到端首版。正式 Model 入口即体验入口，不恢复已删除的开发预览基础设施。

## 布局与交互合同

- Dialog 增加 workbench 布局，桌面约 960 × 680px，受视口与虚拟键盘高度约束；小视口收紧留白。
- 固定标题栏、明确关闭按钮，内容占满剩余空间；业务内容管理滚动。沿用主题 Surface、字体与圆角。
- Model 左侧创建账号，右侧账号/模型列表；窄容器纵向排列。保留原业务控件，不重做账号编辑流程。
- 打开 Model 不替换底下 Panel，不修改其搜索、资源选择和 Timeline；关闭恢复底下现场。浏览器后退可退出浮层，前进可再打开。
- 工具身份写入 Router History State，不写入持久布局；旧 Model 深链与旧存储位置归一化为工具浮层。
- 工具浮层支持点击遮罩关闭，保留 Esc 与关闭按钮；关闭不回滚已提交配置。内部确认可显式禁用遮罩关闭。
- 同时只有一个主要工具浮层。内部可以打开普通确认 Dialog，浏览器 Top Layer 决定层级，不用 z-index 模拟。
- 子 Dialog 的 cancel/close 事件不得冒泡关闭父 Dialog；Esc 只退出最上层。子层关闭回到父层触发点，父层关闭回到原入口。
- 删除 Provider 账号使用普通确认 Dialog，作为真实嵌套流程；失败保留确认与错误，提交期间禁止退出该确认。
- 模型搜索展开时先处理 Esc 收起搜索结果，避免同时退出工具。

## 文件职责

- packages/loom-ui/src/component/dialog.tsx、styles.css：通用布局与嵌套事件隔离。
- shared/studio-shell/studio-workspace.ts、use-studio-navigation.ts：工具导航、恢复和持久化边界。
- pages/studio：浮层宿主与活动入口，不实现 Provider 业务。
- widgets/model-panel：账号表单/列表的空间布局、删除确认与局部反馈。
- i18n：新增确认文案，覆盖现有四语言。
