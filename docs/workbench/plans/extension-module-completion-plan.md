## 本轮文件边界与验证

SDK/Manifest 负责来源和依赖声明；Server 安装器及管理器负责候选获取、
身份核验和安装替换；Kernel RPC 与 Client 扩展中心负责确认清单和操作。
宿主存储复用已有按扩展/安装作用域隔离的 SQL 接口，新增 Server 文件目录入口。
Release 负责携带轻量内容，不修改独立官方仓库或代为构建。
主验证采用远程候选/安装器与管理器的聚焦测试，公共类型变化后运行应用构建。

实时检查：LS_STBridge main 缺少 Manifest 声明的 dist/index.js，且无 Release；
LS_The_World main 缺少客户端构建产物，已发布标签没有成品附件。
因此首次官方下载不能以源码包冒充可运行发行；这是外部产物阻塞，不自动执行构建。

## 目标与已确认边界

让玩家通过远程链接安装独立发行的扩展，不依赖主程序仓库内的开发扩展目录。
覆盖 GitHub 与其他 Git 托管来源；ZIP 不作为玩家主要安装流程，
但可以作为远程发行载荷或离线辅助方式。

沿用现有扩展安装、发现、Manifest 校验和模块授权体系，不建立平行安装器。
安装、授权与启用是不同动作，不能因来源标记为官方而自动授权。
ST 兼容导入和 The World 均为独立、可选扩展；
ST 导入是前期过渡扩展能力，不是主程序原生能力或启动前提。

本计划承接[发布计划归档](../../archive/plans/node-release-and-player-installation-plan.md)。
Beta 主程序的统一启动与发行目录已交付，不在此重复改造。

## 代码位置与开发流程

用户数据目录不存放扩展源码、dist 或其他可执行文件。
应用目录的 `extensions/` 承载扩展代码，包括远程安装的扩展及本地开发扩展。
目录按发布周期而不是官方身份区分：`official/extensions/` 只保留随主程序发行的轻量内容，
STBridge、The World 等独立发行扩展统一在根目录 `extensions/` 安装和开发。
2026-10-02 已将本地开发副本从 `official/extensions/st-data-compat`、
`official/extensions/the-world` 分别移到 `extensions/st-data-compat`、
`extensions/the-world`，保留源码、dist、资源和开发文件；不自动授予权限或启用。
主仓库继续忽略这些独立扩展，搬迁不代表远程仓库已提供可执行产物。
开发者可以直接在扩展目录编写 src、构建 dist，由 Manifest 声明产物入口；
不要求搬到 Application Support，也不以新增 CLI 为前提。
正式模式应能发现并加载这些扩展；构建后通过现有重载能力应用修改。
自动监听尚未决定，不将“文件已构建”描述为“运行中的模块已自动更新”。
dev-link 保留为外部开发目录的可选入口。

远程管理与本地开发来源必须可区分。更新不能覆盖开发者未提交的修改；
同 ID 多来源不能静默选择或互相覆盖。

## 可执行内容、依赖与生命周期

安装来源必须携带 Manifest 所声明的可执行内容，不要求源码主分支提交 dist。
作者可以在源码分支忽略 dist，在独立发行分支提供 Manifest、构建产物和资源；
或者上传 Release 成品 ZIP，由玩家通过远程附件链接安装。
托管平台自动生成的源码 ZIP 不等于可运行发行包。
重型扩展优先使用 Release 成品，轻量纯 JS 扩展可以直接使用 Git。
首版 Release 附件沿用固定 ZIP 链接，不自动查询平台“最新版”；
后续发行版本索引与成品更新检测单独补充，不与源码 Git ref 的更新检测混用。
不强制使用 dist：
依赖打包或转译的扩展自行提供 dist，轻量纯 JS 可以直接声明 src 中的可执行入口。
安装器不执行 npm/pnpm install、构建或生命周期脚本，也不借用主应用依赖补齐扩展环境。
可执行性不能只通过文件存在判断，实施前须核对当前 Client/Server 模块加载合同；
未准备好的依赖由作者解决，不能安装后静默代为构建。

开发语言和框架由作者选择：TS 编译为 JS，TSX/React 和 Vue 单文件组件
转译、打包为浏览器可加载的 JS/CSS，并携带所需运行依赖。
Manifest 指向发行产物，宿主不承担 TS/TSX/Vue 编译，
也不承诺直接运行 TS 或借用主程序的 React/Vue 依赖。
Client Renderer 接收 HTMLElement，扩展自行挂载框架界面并负责销毁；
复用现有 Renderer 合同，不为 Vue 另建插件系统。

扩展间依赖在 Manifest 中声明，可以提供对应扩展的远程安装链接。
声明字段、版本约束和依赖解析先核对已有 Manifest 合同；
链接只用于定位来源，不自动授予信任或权限。
缺失依赖统一列出清单，经用户确认后一起安装，而不是要求逐个手动安装；
依赖仍独立授权，不因批量安装而自动启用。
依赖沿用 Manifest 扩展 ID，不新增 UUID，不以仓库 URL 取代身份；
声明 ID、版本要求及 Git 或 ZIP 来源。下载后核对实际 Manifest ID 与版本，
已有同 ID 不同来源不能自动替换。链接与 ID 都不是来源认证。
本地开发扩展可以满足依赖，不因声明远程链接而重复安装。

## 分发来源与更新检测

- Git：首版使用公开 HTTPS 克隆地址，基于标准 Git 获取，
  不绑定 GitHub API，也不逐个平台实现专属适配。使用此路径需要系统 Git；
  缺失时明确提示，不能让 ZIP 安装也依赖 Git。
- 保存远程来源、所选分支/Tag 与实际 commit。
  分支更新通过远端 ref 的 commit 与安装记录比较；
  固定 Tag/commit 不自动追踪“最新版”，用户主动选择版本。
  查询失败应报告失败，不显示为已是最新；commit 变化不等于版本号更高。
- ZIP：支持本地文件及远程下载链接，均作为现成包安装；
  下载地址不是默认更新源，宿主不提供 ZIP 自动检测更新。
  用户手动导入新版，扩展可以自行提示更新，但不能绕过宿主替换校验与新增权限授权。

不接入私有仓库凭据、SSH 或任意 Git 协议；来源输入与重定向等安全校验仍须定向设计。
分支切换、更新和回退共用候选代码替换流程，不在正在运行的目录直接 checkout。

## 初次启动与官方内容

首次使用时弹出官方内容选择窗口，询问是否下载重型可选扩展，
使用复选框分别选择 ST 数据导入与 The World，并允许跳过。
两者保持独立发行与可选身份，不随主程序自动安装，也不作为开始游玩的前提。
用户确认选择后通过同一远程安装及依赖清单流程下载；
安装、权限授权与启用仍分开处理，不因“官方”身份自动授予权限。
扩展工作台只保留一个“安装扩展”入口；弹窗内分别选择远程链接、
本地 ZIP 或官方推荐。官方列表是快捷来源，不是独立安装系统；
首次提示复用同一弹窗并默认显示官方推荐。
更新、ref 切换与回退属于所选扩展详情，不放到全页面安装栏。

助手、图包等轻量内容默认随主程序携带，不要求独立仓库或首次额外下载。
纯资源不强制包装成可执行扩展；确有代码模块的内容仍遵守授权合同。
具体默认内容清单、来源和资产许可需核对现有包，不把整套 Website 素材自动视为发行清单。

首次选择状态按用户配置持久化，不每次启动或每次升级重复弹出；
跳过、取消和下载失败不阻断主应用使用，之后可从扩展中心重新进入官方安装列表。
远程安装就绪后再接入弹窗，不交付只有选择界面、没有实际下载能力的占位流程。

Git 更新或分支切换遇到本地修改时拒绝覆盖，由用户自行处理；
不自动 stash、丢弃修改或 reset。更新新增权限须重新授权，
不能沿用旧授权直接执行新增权限。

卸载默认保留扩展数据，提供默认不勾选的“同时删除扩展数据”复选框；
显式删除须按现有安装及存储作用域处理，不误删其他角色或安装的数据。
更新和回退仍只处理代码，不恢复或降级数据。

用户确认当前没有需要兼容的用户安装，不制作旧安装目录迁移。
直接调整新安装和发现路径，不保留旧路径兼容；
不因此新增启动时清空用户数据或自动删除旧目录的操作。

## 扩展数据隔离

- 文件与 JSON 存于用户数据根下的 `extensions/<扩展 ID>/`，
  不随意写入 Data 根目录、其他扩展目录或扩展代码目录。
- SQL 数据通过宿主提供的扩展存储接口按扩展身份隔离，
  不直接操作主应用业务表；先核对和复用已有存储作用域，不默认新建数据库或存储框架。
- 数据目录和 SQL 身份由宿主依据调用扩展确定，
  不允许扩展传入任意 ID 获取其他扩展的数据。
- 更新、切换分支和代码回退不改动扩展持久化数据；
  数据格式演进与旧代码兼容由扩展负责，不承诺数据回退。
- 在代码目录存放持久化数据属于违反开发规范，
  安装器不为此新增自动搬迁或备份兜底。

这是宿主接口的作用域隔离与开发规范，不是同进程 Node 扩展的安全沙箱；
不能宣称阻止恶意扩展绕过接口直接访问文件或数据库。
已有全局/角色等安装及存储作用域需保持其归属边界，
具体文件布局在核对现有合同后确定，不因引入扩展目录而合并不同作用域。

## 验收与非目标

失败不能留下可被当作成功安装的半成品，也不能破坏已有扩展或用户数据。
具体可执行命令和测试范围在合同确认后补齐。

以及宿主接口不能通过伪造扩展 ID 访问其他扩展的数据。

本地修改不被更新覆盖，新权限未获授权不得执行，默认卸载保留数据。
验证 Git 不依赖 GitHub 专属接口，ZIP 无 Git 也可安装且不显示自动更新检测；
首次官方选择可跳过，失败不阻断游玩，重启不重复弹窗，仍可从扩展中心重新选择。

不实施 npm 主程序发行、Electron、移动端、自动更新框架或凭据明文降级。
