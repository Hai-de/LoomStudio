# Loom Script 单文件分发与运行计划

> **状态**：讨论记录 / 核心方向已确认，未授权业务实施
> **更新**：2026-10-18
> **目标**：将 Script 从轻量 Renderer 格式扩展为通用单文件代码分发形式，复用扩展的运行环境和宿主能力。
> **本轮授权**：记录决定及依赖、登记索引；不修改运行实现、权限、存储或用户数据。

## 1. 已确认的产品定位

- Script 是比 Extension Package 更轻便的代码分发形式，Metadata 写在文件头部，不需要独立 Manifest。便于角色卡携带、单独分享及未来网络平台托管。
- 单文件是最终分发形式，不限制作者使用 TypeScript、多文件源码或构建工具开发。
- 渲染只是脚本的一项能力，不能继续用 Renderer 定义整个 Script。
- 作者和 AI 均可编写、修改和启动脚本。AI 调用不意味着只能按次执行；AI 启动的程序也可以持续运行。
- 扩展包本身可以携带独立脚本，不要求把该脚本改写成扩展模块。
- State 事件、动态 Prompt、Lore 激活等钩子属于整个扩展能力面，扩展和脚本均应能够使用；不为 Script 建立另一套独立业务 API。

## 2. 当前实现事实与入口

本节来自本轮定向源码阅读，未执行运行测试；后续实施前只需核对涉及部分的变化。

- [现有 Script 合同](../../architecture/extensions/loom-script-runtime.md)及 [Metadata codec](../../../packages/application-runtime/src/scripts/loom-script-codec.ts)：当前仅接受 `client-sandbox` 和 Renderer contribution；身份、挂载及导入导出已存在。
- [Script Runtime](../../../packages/application-runtime/src/runtime/loom-scripts-runtime.ts)：源码以 Blob 保存，Document 保存 Metadata、源码引用、摘要和版本，Mount 保存采用关系与授权。当前不是可直接编辑的宿主源码目录，也不是把源码全文直接存进脚本文档。
- [Blob Store](../../../packages/blob-store/src/store.ts)：字节文件与 SQL 元数据协作；这一现状不决定后续工作区存储选择。
- [CodeAct 合同](../../architecture/application/agent/tool-system.md)：已有按次 QuickJS 执行及脚本附件读取；附件读取不等于正式文件执行入口，也不代表持久代码实例已经实现。
- [Extension SDK](../../../packages/extension-sdk/src/index.ts)及 [Host](../../../packages/extension-sdk/extension-host/src/instance.ts)：已有 State 订阅与实例注销。
- [Prompt Processor](../../../packages/extension-sdk/src/prompt-processing.ts)：已有按构建处理采用条目的正文及本轮激活结果的接口。它不是已经接好的任意脚本动态 Prompt 入口。

## 3. 执行环境与权限

### 已确认

脚本与扩展一样声明运行环境。用户不接受将首版主动收窄为仅 iframe，或预先排除其他环境。设计应覆盖 iframe、Worker、受控 JavaScript 沙箱、受信任 Client / Server 同进程执行及独立进程等讨论中的环境，并核对可复用执行器和缺口；不能仅增加声明字段就声称对应环境已支持。

分发形式、执行环境、能力授权和生命周期分别表达。沙箱化程度不由“作者写的还是 AI 写的”决定。未来允许 AI 启动持久执行实例，不把 CodeAct 当前按次释放的实现冻结成所有脚本的限制。

### 实施约束与待收束项

- 运行环境声明是请求，不自行授予权限；沿用宿主授权边界。
- 脚本本体同进程执行、只把渲染内容放进 iframe，不等于整个脚本受到 iframe 隔离。
- 不支持或未获授权的运行目标应明确不可用，不静默切换到权限更大的环境。
- 各环境的具体名称、入口形状、跨边界调用、终止能力与首版交付缺口，须在实施设计中逐项列出；如实际需要缩减已要求的范围，应向用户说明并决定。

## 4. 文件模型与 Timeline 工作区

### 已确认

脚本可以作为文件内容来源，但不锁定为真实磁盘文件。SQL 正文、Blob 或包内真实文件均可能成为底层实现，运行时按身份及版本取出代码即可。不得将用户此前偏好文件理解为已批准迁移到物理目录。

脚本接入 [Timeline 工作空间与 VFS 组织计划](./timeline-workspace-and-vfs-organization-plan.md)。该计划决定工作树身份、内容存储、并发与历史恢复；脚本系统不另建一套目录权威或独立回滚系统。随包文件与游玩生成文件可以采用不同存储。

### 建议，尚非已冻结合同

- 普通辅助代码文件不必立即成为带完整 Metadata 的正式 Script；需要平台发现、管理、分发和启动时再采用正式脚本协议。
- 文件定义、挂载关系和运行实例分别管理。稳定 ID 不依赖显示名称、文件名或下载地址。
- AI 游玩产物与作者原件分开，更新原件、创建派生副本及普通保存的具体权限与交互仍需收束。

## 5. 保存与刷新

### 已确认

- 保存代码不自动重启正在运行的脚本。
- 提供独立刷新按钮重新加载脚本，不要求整个页面刷新，也不要求切换角色。
- 刷新必须处理旧实例的停止与新实例的加载，不能简单再执行一次文件而保留旧监听器、定时器和闭包。

### 实施建议

实例绑定启动时采用的内容版本，界面可区分已保存版本和运行版本。准备及校验新代码后，停止并清理对应旧实例，再启动新版；启动失败明确展示。宿主托管资源可以清理，不能承诺任意同进程代码的副作用都可撤销。

刷新作用于选中采用范围还是该文件的全部实例、下一次按次调用采用哪个保存版本、失败后能否恢复旧实例及恢复范围，尚需实施合同明确。刷新不应无差别停止其他角色或全局实例。

## 6. 来源、采用范围与后台生命周期

### 已确认

| 情形 | 行为 |
| --- | --- |
| 全局脚本，包括全局扩展携带的独立脚本 | 可以全局运行，不因角色或 Timeline 切换而默认停止 |
| 当前角色携带并启用的脚本 | 随角色切换而卸载、加载；同角色切换 Timeline 不以此重启脚本 |
| 显式停用脚本或其运行范围 | 停止对应实例 |
| 服务重启 | 按已保存的启用配置重新启动；不恢复旧内存，不默认补放停机期间的事件 |

包负责携带代码；来源归属与实际采用范围需要分别表达，不能把“来自全局扩展”硬编码成只允许全局实例。

### 实施建议与未决边界

- 同角色切换 Timeline 时保留角色实例，但更新上下文、重绑相关订阅；已发出的异步操作不能因为当前界面切换而写入新的 Timeline。
- Context 撤销、在途操作目标绑定与过期提交拒绝，应复用现有执行和恢复边界。
- Timeline 工作区内创建并启动的脚本需有独立的归属语义；切离后是否持续执行、何时停用，尚未单独确认，不能套用角色切换规则。
- 剧情回滚不一律重启全局或角色实例。工作区代码、启用配置和内部持久状态如何恢复，以及哪些实例必须失效或重建，交由统一 Timeline 恢复合同收束；不得恢复文件后仍让过期实例无约束提交。
- 多窗口、同一角色同时打开不同 Timeline 时，“当前角色”和实例唯一性的宿主范围尚待明确。

## 7. 外部依赖与更新

### 已确认

允许外部 assets、CDN / 图床图片和代码依赖；不要求全部内嵌，不采用首版一律禁止远程依赖的建议。单文件描述分发入口，不保证所有依赖都在文件内。

### 待收束

- 外部代码依赖的声明、解析基准、顺序、缓存、内容版本或摘要，以及加载失败时是否能启动。
- 资源随包导出与保留外链的规则，离线缺失的说明。
- 网络能力与依赖下载责任；各运行环境不能借加载依赖绕过其权限合同。
- 托管和下载不等于已批准自动更新。更新来源、远程内容变化、本地修改冲突、新权限确认及正在运行实例的处理仍需设计。

## 8. 共用能力面的衔接

已确认的实际需求包括作者根据好感度激活世界书、根据世界天数触发事件，以及 AI 保存可复用代码并启动后台世界演进。不能把这些需求归为仅 AI 使用或仅渲染使用。

讨论中的建议是区分两种语义：PromptBuild 根据本次 State 快照计算本轮内容；State 变化钩子处理需要发生并持久记录的事件。两者可以组合，但钩子、Prompt Contribution、消息投递和 Agent 触发的公共合同属于共用扩展能力面，不在本计划内另创一套。

相关 [Agent 通用触发计划](./agent-trigger-and-standing-resource-bindings-plan.md) 与 [CodeAct / VFS 计划](./codeact-vfs-tooling-plan.md) 负责各自入口。脚本持续运行不自动授予消息发送或 Agent 调用能力。

## 9. 单文件协议的设计参考

以下是从用户脚本生态讨论得到的建议，不是已全部批准的字段或机制：

- 静态解析 Metadata，建立索引和导入时不执行源码；明确格式版本、重复字段和未知执行声明的处理。
- 身份独立于名称；Metadata ID 和作者字段不证明来源可信，重导入需区分更新和副本。
- 权限请求与隔离环境分开，避免“无权限声明反而获得直接宿主访问”的歧义。
- 作者发布版本与实际内容摘要分开，避免 AI 每次保存都必须发布新版本。
- 显式运行入口及宿主追踪的清理机制，避免停用、刷新后残留重复订阅。

参考：[Tampermonkey 权限语义](https://www.tampermonkey.net/documentation.php?locale=en&q=grant)、[外部依赖与完整性](https://www.tampermonkey.net/documentation.php?locale=en&q=externals)、[Violentmonkey Metadata](https://violentmonkey.github.io/api/metadata-block/)。参考用于设计比较，不要求兼容其协议。

## 10. 后续工作与验收方向

下一步先制定运行环境支持矩阵、Metadata / 入口契约、来源与采用范围映射，再结合 Timeline 工作区收束存储和恢复接口。改变权限、存储或恢复公共语义前，应确认未决项；当前没有授权直接实施整个脚本重构。

后续验收至少覆盖：非 Renderer 脚本正常采用；扩展携带独立脚本；每种声明环境真实执行且无静默提权；保存不重启、局部刷新后只有一个有效实例；角色切换卸载与同角色 Timeline 切换保留；旧异步结果不写错目标；外部依赖成功及失败路径；服务重启按配置重建。工作区回滚专项在统一恢复合同定稿后补齐，不自行承诺现已具备。

本轮只检查文档 Diff、索引和链接，不以此宣称运行能力或浏览器验收通过。

历史背景：[早期 Script / Script Mount 候选](../../archive/plans/file-backed-resource-agent-script-codeact-plan.md)。当前方向以本计划及其依赖计划为准，不自动恢复旧稿中的全部候选范围。
